on a GPU errand.

GPU Errand lets Claude Code, Codex or any coding agent run a job on a Google Colab GPU. It never runs past the compute units you allowed, and it brings the results back with a receipt.

pipx install git+https://github.com/GanglyPuma22/gpu-errand

How an errand runs

Your agent writes the job.

One JSON file: the commit to run, the command, the GPU and the most it may spend.

{
  "schema": 1,
  "id": "hello-pr1",
  "type": "shell",
  "repo": "GanglyPuma22/gpu-errand",
  "ref": "79d34a6",
  "command": "nvidia-smi > $OUT_DIR/gpu.txt",
  "gpu": "T4",
  "max_minutes": 3,
  "max_units": 0.1,
  "max_rate": 3
}

Then you read the plan and say go.

gpu-errand plan prints every step with its caps. Nothing is spent before you agree.

$ gpu-errand plan hello-pr1.json
host: git fetch, git archive 79d34a6
      (no .git, no credentials)
host: colab new --gpu T4
host: read the hourly rate; refuse an
      unknown rate or one above 3 units/h;
      cap the runtime at 3 min + 20
      or 0.1 units, whichever comes first
runtime: run: nvidia-smi …
host: check every file, stop the runtime

agent: Go? This spends up to 0.1 units.

Your machine runs it on Colab.

It waits for a free GPU, reads the rate, and stops the runtime at the cap, even if something hangs.

Safe to hand to an agent

GPU

On a T4 at 1.07 units an hour, the runtime is stopped after 5 min 36 s, by the unit cap. It can spend at most 0.1 units, about 1 cent.

A cap that holds

Once the GPU is granted, the runner reads the account's hourly rate. It refuses an unknown rate or one above max_rate, then stops the runtime at the time cap or the unit cap, whichever comes first.

If a stop fails, it keeps trying for 30 minutes. Try the numbers: the rates are ones we saw on one Pro account in October 2026, and the runner reads yours.

Results you can check

The runtime lists every output with its SHA-256 before anything leaves. Your machine checks each file against that list, and drops links and special files.

Model runs add receipt.json with each output's length, peak and loudness. A silent or broken file fails the run.

Nothing secret leaves home

Only the job's commit and two scripts go to the runtime. Gated Hugging Face weights come through short-lived download links your machine makes, so the token never travels.

The job file refuses environment variables that look like keys or passwords.

Your go, every time

The agent skill shows you the plan and the cap, then waits. A go covers that job and those caps, nothing more.

For a standing queue, agents push job files to a branch of a private repo. Your machine works through them only after you type go, inside the bounds you set.

Questions

Is this a Google product? No. It's an independent open-source tool that drives Google's own Colab CLI.

Does it work on the free Colab tier? No. Colab allows remote shells only on paid accounts with compute units left.

How is it different from Modal, RunPod or SkyPilot? Those rent GPUs by the second. GPU Errand is for people who already pay for Colab and want an agent to use those units safely.

Which agents does it work with? Claude Code through the plugin, Codex through the skill folder, and anything else that can run a shell command.

Can my agent raise its own cap? No. The cap is in the job you approved, and a go covers that job only. On a failure the skill reports back instead of retrying.

What does the host need? Linux, macOS or WSL with git, ssh, Python 3.9 or newer, and the Colab CLI signed in. The CLI doesn't run on plain Windows.

Can a cloud agent use it? Yes, through the queue. It pushes a job to a private repo and reads the results branch later, while your machine does the running.

Who checks the model licenses? You do. Stable Audio Open uses the Stability AI Community License, and ACE-Step lists its terms on its repository.
